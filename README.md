# Арифметические схемы разделения секрета на основе RS-кодов

Исследовательский прототип для ВКР «Кодовые конструкции арифметических схем
разделения секрета: коды Рида–Соломона, мультипликативность и конкатенация».
Основные конструкции реализованы самостоятельно на Python 3.11+ со стандартной
библиотекой; внешних математических зависимостей нет. Приоритет — прозрачность
алгоритмов и математическая корректность, а не универсальная криптобиблиотека.

## Установка и проверка

Из корня репозитория:

```bash
python3 -m venv .venv
source .venv/bin/activate
python -m pip install -e '.[dev]'
python -m pytest -v
```

предназначен для реальных секретов. После установки модули импортируются из
любого рабочего каталога. Каталог `results/` создаётся только при явном запуске
генератора подробного отчёта, описанного ниже; `experiments/` не создаётся.

## Поле и соглашения

`PrimeField(p)` представляет GF(p) целыми числами `0, ..., p-1`. Операции принимают
и другие целые представители, нормализуя их по модулю p. `contains` проверяет
именно канонического представителя. `bool` и нецелые аргументы отклоняются.
Нулевая степень, включая `0**0`, равна единице; отрицательная степень использует
обратный элемент и запрещена для нуля. Простота проверяется точным пробным
делением до квадратного корня: O(sqrt(p)) делений, без вероятностного допущения.
Это подходит для небольших и средних параметров прототипа, но не для огромных
криптографических простых чисел.

Элементы представлены обычными `int` и не несут метку поля. Владелец операции
определяет модуль; происхождение отдельного целого из другого поля определить
невозможно. Объекты многочленов и схем хранят поле, а операции над такими
объектами запрещают несовместимые модули. Два экземпляра GF(p) с одинаковым p
считаются одним полем.

Коэффициенты многочлена идут от свободного к старшему. Единственное представление
нуля — `(0,)`, степень нулевого многочлена — `-1`. Интерполяция не принимает пустой
набор и повторяющиеся абсциссы, в том числе совпадающие после нормализации.
`Polynomial.random` генерирует **точную** степень с ненулевым старшим коэффициентом;
Шамир использует другой закон: все t коэффициентов независимы и равномерны,
включая нули. Поэтому степень многочлена Шамира может быть меньше t.

В схеме Шамира n — число участников, t — порог приватности, k=t+1 — минимальное
число долей для восстановления. Требуется `0 <= t < n <= p-1`. Точки участников
различны и ненулевые. В RS-коде k — размерность кода; допускаются нулевые точки
и `1 <= k <= n <= p`. Для связи с Шамиром нужно задать одинаковые точки и k=t+1.

```python
from field import PrimeField
from polynomial import Polynomial, interpolate, lagrange_weights

field = PrimeField(17)
assert field.add(12, 9) == 4
assert field.mul(5, 7) == 1
assert field.inv(5) == 7
assert field.div(10, 5) == 2
f = Polynomial(field, [3, 2, 1])
points = [(x, f(x)) for x in [1, 2, 4]]
assert interpolate(field, points) == f
weights = lagrange_weights(field, [1, 2, 4])
assert sum(w * y for w, (_, y) in zip(weights, points)) % field.p == f(0)
assert (f * f)(3) == field.mul(f(3), f(3))
```

## Шамир и кодовая интерпретация

Для секрета s выбирается `f(X)=s+a_1 X+...+a_t X^t`, участник i получает
`(x_i, f(x_i))`. Вектор значений принадлежит RS(n,t+1); секрет — дополнительная
координата вычисления при X=0. API не хранит секрет или исходный многочлен внутри
объекта схемы. `reconstruct` использует только предоставленные доли и публичные
параметры, требует не менее k долей и проверяет согласованность лишних долей.

Любые k долей определяют многочлен интерполяцией. Для m<=t наблюдений матрица
отображения случайных коэффициентов в наблюдения имеет ранг m: первые m столбцов
образуют невырожденную матрицу Вандермонда, умноженную на ненулевые x_i.
Поэтому каждый вектор наблюдений встречается ровно p^(t-m) раз для любого s.
Это доказательство совершенной t-приватности; статистический тест её не доказывает.

```python
from random import Random
from shamir import ShamirScheme

scheme = ShamirScheme(field, n=7, t=2)
shares = scheme.share(9)  # SystemRandom по умолчанию
assert scheme.reconstruct([shares[i] for i in [0, 3, 6]]) == 9
# Воспроизводимый исследовательский вход:
assert scheme.share(9, Random(42)) == scheme.share(9, Random(42))
```

## RS-коды и квадрат кода

RS(n,k) состоит из векторов `(f(x_1),...,f(x_n))` при `deg f < k`.
Порождающая матрица имеет строки `(x_i^j)_i`, `j=0,...,k-1`.
Размерность k следует из инъективности вычисления при n>=k, минимальное расстояние
`d=n-k+1` — из ограничения числа корней ненулевого многочлена. Оценка достижима
для произведения k-1 различных линейных множителей на точках кода.

`decode` принимает пары **(индекс координаты от 0, значение)**, а не абсциссы.
Это восстановление при стираниях; исправления ошибок здесь нет.

```python
from reed_solomon import ReedSolomonCode
from linear_algebra import rank, rref

code = ReedSolomonCode(field, n=7, k=3, points=scheme.points)
word = code.encode([9, 2, 5])
assert code.decode([(i, word[i]) for i in [0, 3, 6]]) == Polynomial(field, [9, 2, 5])
assert rank(field, code.generator_matrix()) == 3
reduced, pivots = rref(field, code.generator_matrix())
assert len(pivots) == 3
assert (code.n, code.k, code.d) == (7, 3, 5)
```

Покомпонентное произведение определяется как `c*c'=(c_i c'_i)_i`.
Квадрат кода — линейная оболочка всех таких произведений:
`C^{*2}=span{c*c': c,c' in C}`. По билинейности достаточно перемножить строки
порождающей матрицы попарно; используются пары i<=j, включая квадраты строк.
Базис получается методом Гаусса над GF(p), а не подстановкой формулы размерности.

Для обычных RS-кодов на одних точках произведения мономиальных строк дают все
степени от 0 до 2k-2. Если `2k-1 <= n`, это RS(n,2k-1). Если `2k-1 >= n`,
первые n мономов уже порождают всё GF(p)^n. Поэтому
`RS(n,k)^{*2}=RS(n,min(n,2k-1))` и `dim C^{*2}=min(n,2k-1)`.

```python
from code_square import CodeSquare, componentwise_product, generator_products

square = CodeSquare(field, code.generator_matrix())
assert square.dimension == 5
local_word = componentwise_product(field, word, word)
products = generator_products(field, code.generator_matrix())
assert rank(field, [*square.basis, local_word]) == square.dimension
assert rank(field, products) == square.dimension
small = ReedSolomonCode(PrimeField(5), n=4, k=2)
assert small.minimum_distance() == 3
assert CodeSquare(small.field, small.generator_matrix()).minimum_distance() == 2
```

Перебор минимального расстояния общий для исходного и квадратного кодов. Он
перебирает линейные комбинации независимого базиса и вычисляет вес ненулевых слов.
По умолчанию разрешено не более `max_words=100_000` комбинаций; превышение
отклоняется **до** начала перебора. Предел можно явно изменить. Для нулевого кода
минимальный ненулевой вес не определён, и API выбрасывает `ValueError`.
Гаусс принимает прямоугольные матрицы, включая пустые и вырожденные.

## Умножение и сильная мультипликативность

Для двух независимо разделённых секретов a,b участник умножает свои значения:
`h_i=f(x_i)g(x_i)`. Это вычисления многочлена h=fg степени <=2t, и h(0)=ab.
Любые 2t+1 точек дают линейное восстановление произведения, веса которого
вычисляются по формуле Лагранжа. `multiply_shares` сопоставляет доли по точкам,
поэтому порядок двух входных наборов может отличаться.

```python
from multiplication import (
    is_multiplicative, is_strongly_multiplicative,
    multiply_shares, product_reconstruction_weights, reconstruct_product,
)

left, right = scheme.share(4), scheme.share(6)
local = multiply_shares(scheme, left, right)
assert reconstruct_product(scheme, local[:5]) == field.mul(4, 6)
weights = product_reconstruction_weights(scheme, [x for x, _ in local[:5]])
assert sum(w * y for w, (_, y) in zip(weights, local[:5])) % field.p == 7
assert is_multiplicative(scheme)             # n >= 2t+1
assert is_strongly_multiplicative(scheme)    # n >= 3t+1
```

В принятой модели линейной реконструкции стандартный Шамир мультипликативен при
`n >= 2t+1`. После удаления любых <=t участников эта возможность сохраняется
тогда и только тогда, когда `n-t >= 2t+1`, то есть `n >= 3t+1`.
Это сильная мультипликативность относительно всех t-приватных множеств.

Недостаточность числа наблюдений — не только ограничение API. Для m<=2t ненулевых
точек можно разбить их на два множества размера <=t и взять f и g как произведения
соответствующих `(X-x_i)`. Тогда все наблюдаемые f(x_i)g(x_i) равны нулю,
но f(0)g(0) ненулево. Эти наблюдения совпадают с произведением нулевых секретов.
Кроме того, вычисляемая тестами система для универсальных линейных весов
несовместна: вектор `(1,0,...,0)` не лежит в пространстве строк матрицы
`(1,x_i,...,x_i^(2t))`. Умножения мономов степени <=t порождают все эти степени,
поэтому условие относится именно к настоящим произведениям.

Локальные произведения не являются новым t-приватным разделением по исходной
схеме. Их распределение не обязано быть равномерным по многочленам степени <=2t.
Понижение степени, повторное разделение и полноценный MPC-протокол не реализованы.

## Реализованная конкатенация: HierarchicalShamirComposition

Выбрана явно разрешённая постановкой **двухуровневая композиция Шамира над одним
простым полем**. Соответствие специальной конкатенации Cramer–Xing–Yuan не
установлено: определения и свойства той конструкции этому классу не приписываются.
Это ограничение научного охвата прототипа.

Пусть внешние параметры — `(n_o,t_o)`, внутренние — `(n_i,t_i)`.

1. Выбирается `F(X)=s+sum_{a=1}^{t_o} A_a X^a`.
2. Для каждого внешнего участника i независимо выбирается
   `G_i(Z)=F(x_i)+sum_{b=1}^{t_i} B_{i,b} Z^b`.
3. Конечный участник `(i,j)` получает один элемент `G_i(z_j)`.
   Всего участников `n_o*n_i`. Все A и B независимы и равномерны в GF(p).
4. При восстановлении сначала интерполируются константы G_i в блоках с
   `t_i+1` наблюдениями; затем по `t_o+1` таким константам восстанавливается F(0).

Индексы `(i,j)` в `CompositeShare` начинаются с нуля; это публичные идентификаторы,
которые преобразуются в точки `outer.points[i]` и `inner.points[j]`.
Поля обоих уровней должны совпадать. Точки двух уровней могут отличаться.

Это линейная схема: вектор окончательных значений линейно зависит от
`(s, A_1,...,A_{t_o}, B_{0,1},...,B_{n_o-1,t_i})`.
В терминах RS внешнее слово принадлежит RS(n_o,t_o+1), а внутреннее слово блока
принадлежит RS(n_i,t_i+1), причём его **значение в нуле**, а не произвольный
коэффициентный вектор, равно внешней доле. Каждый блок использует независимую
внутреннюю случайность. Это не обычное детерминированное конкатенирование кодов
через отображение символа расширенного поля в вектор над подполем.

### Точная структура доступа и приватность

Пусть `r_i` — число имеющихся листьев блока i. Множество авторизовано ровно при
`#{i: r_i >= t_i+1} >= t_o+1`. Неполные блоки при восстановлении не используются.
Утверждение «ровно» обосновывается также приватностью всех остальных множеств:

- В блоке с r_i<=t_i внутренние наблюдения равномерны и не зависят от F(x_i).
  Независимость внутренних коэффициентов делает такие наблюдения независимыми
  от всего внешнего многочлена и от наблюдений других блоков.
- В блоке с r_i>=t_i+1 наблюдения определяют внешнюю долю F(x_i). Условное
  распределение остальных данных этого блока зависит от F(x_i) и свежей внутренней
  случайности, но не даёт дополнительной информации о F или s.
- Неавторизованное множество имеет не более t_o таких полных блоков. По приватности
  внешнего Шамира их доли и, следовательно, все наблюдения не зависят от s.

Таким образом, каждое неавторизованное множество совершенно приватно, а каждое
авторизованное восстанавливает s. В общем случае это **не пороговая** схема.
Например, при `(n_o,t_o)=(3,1)` и `(n_i,t_i)=(2,1)` распределение четырёх листьев
по блокам `(2,2,0)` авторизовано, а `(2,1,1)` — приватно.

Полезные границы мощности, не заменяющие блочное правило:

- минимальное авторизованное множество: `(t_o+1)(t_i+1)`;
- максимальное неавторизованное: `t_o*n_i+(n_o-t_o)*t_i`;
- любые множества размера <= `(t_o+1)(t_i+1)-1` приватны;
- любые множества размера >= `t_o*n_i+(n_o-t_o)*t_i+1` восстанавливают секрет.

Последняя формула для максимума получается заполнением t_o блоков целиком,
а всех остальных — не более чем t_i листьями. Эти значения возвращает
`access_parameters()`. `is_authorized()` и `is_private()` используют полное правило.

### Размер и умножение составных долей

Каждая доля содержит один элемент GF(p), энтропийный размер — log2(p) бит,
фиксированная битовая упаковка требует `ceil(log2(p))=(p-1).bit_length()` бит.
`share_size_bits` возвращает только этот полезный размер, без публичных индексов,
накладных расходов объектов Python и сериализации. Общий полезный объём —
`total_shares * share_size_bits` бит при такой упаковке.

Для двух независимых композиций локальное произведение в блоке i задаёт
`H_i(Z)=G_i(Z)G'_i(Z)` степени <=2t_i. Из `2t_i+1` листьев линейно восстанавливается
`H_i(0)=F(x_i)F'(x_i)`. Затем из `2t_o+1` таких блоков восстанавливается
`(FF')(0)=ss'`. Произведение двух линейных функционалов по разным уровням даёт
линейный функционал от конечных локальных произведений.

Условие реализации: `n_i>=2t_i+1` и `n_o>=2t_o+1`; для конкретного подмножества
нужны `2t_o+1` блоков с `2t_i+1` листьями каждый. Методы `is_multiplicative()` и
`can_reconstruct_product()` проверяют именно условия этого вложенного алгоритма.
Общая сильная мультипликативность относительно всей составной структуры доступа
здесь не исследована и не гарантируется; отдельного API с таким обещанием нет.

```python
from concatenation import HierarchicalShamirComposition

composition = HierarchicalShamirComposition(
    outer=ShamirScheme(field, n=4, t=1),
    inner=ShamirScheme(field, n=4, t=1),
)
leaves = composition.share(8)
subset = tuple(s for s in leaves if s.block in [0, 2] and s.participant in [1, 3])
assert composition.is_authorized(s.identifier for s in subset)
assert composition.reconstruct(subset) == 8
assert composition.total_shares == 16
assert composition.share_size_bits == 5
assert composition.access_parameters()["minimum_authorized_size"] == 4
assert composition.is_private([(0, 0), (1, 0), (2, 0), (3, 0)])
assert composition.is_multiplicative()
products = composition.multiply_shares(leaves, composition.share(6))
product_subset = tuple(s for s in products if s.block < 3 and s.participant < 3)
assert composition.can_reconstruct_product(s.identifier for s in product_subset)
assert composition.reconstruct_product(product_subset) == field.mul(8, 6)
```

## Что доказано, что проверено и что предполагается

**Математические свойства**, с обоснованиями выше: аксиомы GF(p) при простом p,
единственность интерполяции, приватность и восстановление Шамира, MDS-параметры RS,
формула RS-квадрата, условия линейной мультипликативности и сильной
мультипликативности стандартного Шамира, точная структура доступа и приватность
выбранной композиции, достаточность описанного вложенного восстановления
произведений. Эти утверждения опираются на алгебру и независимую равномерную
случайность, а не на число прошедших тестов.

**Вычислительные проверки реализации**: полный перебор аксиом на малых полях,
арифметические тождества многочленов, интерполяция и все минимальные подмножества
восстановления, точные распределения приватных наблюдений, линейность RS и ранг
генератора, перебор кодовых слов и расстояний, совпадение пространств квадратного
и ожидаемого RS-кодов, замкнутость и все базисные произведения, все пары секретов
для малых полей, перебор удаляемых множеств для сильной мультипликативности,
ранговые свидетельства и явные контрпримеры недостаточности долей. Для составных
схем перебираются все подмножества конечных участников на малых параметрах, а
для одной схемы — все потоки случайных коэффициентов и все приватные коалиции.
В тестах используются GF(5), GF(7), GF(11), GF(17), дополнительно GF(2), GF(101).
Статистическая проверка с фиксированным seed служит только дополнительным тестом.

**Ограничения и предположения**:

- Только простые поля GF(p); GF(p^m) и специальные отображения между полями не
  реализованы. Универсальный backend намеренно не вводится.
- Секрет — один элемент поля. Кодирование строк/байтов и сериализация не входят в API.
- Нет константного времени исполнения, аутентификации долей, защиты от активного
  противника, исправления ошибок, MPC и понижения степени.
- Проверка согласованности лишних долей обнаруживает некоторые ошибки, но при
  минимальном количестве долей любой набор значений интерполируется. Это не
  проверяемое разделение секрета. Неквалифицированные блоки при вложенном
  восстановлении не используются, их значения не проверяются на согласованность.
- Корректность и приватность предполагают честное создание долей и независимые
  равномерные случайные коэффициенты. При явном внедрении RNG это обязанность
  вызывающего кода. Сырые целые значения не имеют меток поля или идентификатора
  запуска; доли разных запусков нельзя смешивать.
- Перебор расстояния экспоненциален и ограничен `max_words`. Даже разрешённый
  перебор может быть дорогим при очень большой длине кода. Проверка простоты не
  рассчитана на криптографические размеры p.
- Теоретическая конкатенация из научной статьи и сильная мультипликативность
  составной структуры не заявляются реализованными.

Параметры n,k,t,p и точки задаются конструкторами, случайность можно внедрять.
Алгоритмы не содержат измерений времени, печати или записи результатов; будущие
бенчмарки смогут измерять генерацию, восстановление и умножение извне и сравнивать
конструкции с явно указанными полями, числом участников, структурой доступа и
размером полезных долей.
